\subsection{Detailed Description}
direct access to file-system, no abstraction layer. 

may be compiled with support for libmagic (the \char`\"{}file\char`\"{} command). if this support was compiled in but the library is not present at run-time, this backend will fall back on a simple filename-extension (\char`\"{}.mp3\char`\"{}) to MIME-type (\char`\"{}audio/mp3\char`\"{}) mapping instead.

may be compiled with support for libacl (for Access Control Lists -- the file-system you use must support these; if they are optional, a mount- option (\char`\"{}acl\char`\"{}) may also be necessary). if this support was compiled in and the library is present at run-time, ACLs and default-ACLs can be viewed and modified in evidence.

may be compiled with support for libattr (for Extended Attributes -- the file-system you use must support these; if they are optional, a mount- option (\char`\"{}user\_\-xattr\char`\"{}) may also be necessary). if this support was compiled in and the library is present at run-time, EAs can be viewed in evidence.

may be compiled with support for F\_\-NOTIFY (on Linux $>$=2.4) and/or libfam (for FAM, the File Alteration Monitor). if F\_\-NOTIFY was compiled in and a suitable kernel is deteced at run-time, F\_\-NOTIFY will be used to learn about changes in the file-system. otherwise, if support for FAM was compiled in and the library is present at run-time and the FAM-daemon speaks with us, FAM will be used. otherwise, this backend will fall back on polling directories as a last resort.

by Azundris
